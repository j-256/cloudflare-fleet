Deployment

Stand up a protected Worker without losing local mode

Hosted Fleet uses a custom-domain Worker, Cloudflare Access, D1, and encrypted Worker secrets. Generated deployment and operator files stay ignored; the committed defaults are safe, read-only, and unscheduled.

Prerequisites

  • Node.js 22 or newer and npm
  • A Cloudflare account with an active zone for the Fleet hostname
  • Permission to create Workers, a D1 database, a custom domain, and a Cloudflare Access application
  • An account API token scoped to the resources Fleet should inspect and, if enabled, change; see the least-privilege starting point
  • A configured Cloudflare Zero Trust team domain and identity provider
Begin read-only

The configuration generator defaults to FLEET_READ_ONLY=true. Inspect the deployed inventory and Access boundary before regenerating with --write.

Hosted path

Provision the Worker

1

Install the pinned toolchain

The lockfile pins Wrangler, the Access JWT library, and the browser test stack. Keep the source checkout for deployment, but install the tagged GitHub package for a durable operator command that does not link back to the checkout.

npm install --global "github:j-256/cloudflare-fleet#v0.1.0"
npm ci
cloudflare-fleet --help
2

Create the D1 database

Record the database identifier returned by Wrangler. The generated configuration binds it as FLEET_DB.

npx wrangler d1 create cloudflare-fleet
export CLOUDFLARE_FLEET_D1_DATABASE_ID="the-returned-database-id"
3

Create the Access application

In Cloudflare Zero Trust, create a self-hosted application for the exact Fleet hostname and attach an Allow policy for the intended operators. Copy the Application Audience tag from the application settings and use the full HTTPS team domain as the issuer. The Worker validates both values on every non-loopback request.

Cloudflare documents the flow in Publish a self-hosted application and explains the audience and issuer in Validate JWTs.

4

Generate the ignored Wrangler configuration

Use an exact custom-domain hostname with no existing CNAME. Cloudflare creates the DNS record and certificate when Wrangler deploys the custom domain.

export CLOUDFLARE_ACCOUNT_ID="your-account-id"
export CLOUDFLARE_ACCESS_AUD="your-access-application-audience"
export CLOUDFLARE_ACCESS_TEAM_DOMAIN="https://your-team.cloudflareaccess.com"

cloudflare-fleet hosted configure \
  --account-id "$CLOUDFLARE_ACCOUNT_ID" \
  --database-id "$CLOUDFLARE_FLEET_D1_DATABASE_ID" \
  --hostname fleet.example.com \
  --access-aud "$CLOUDFLARE_ACCESS_AUD" \
  --access-team-domain "$CLOUDFLARE_ACCESS_TEAM_DOMAIN"

The command writes mode-restricted wrangler.jsonc. That file contains account and deployment identifiers, so Git ignores it. wrangler.example.jsonc documents the portable shape without live values.

5

Apply storage and deploy the secret with the code

Wrangler accepts an ignored dotenv file through --secrets-file, allowing the first code version and encrypted secret to deploy together. Delete the local secret file after deployment if the shell environment is your preferred source of truth.

npm run db:migrate:remote
umask 077
printf 'CLOUDFLARE_API_TOKEN="%s"\n' "$CLOUDFLARE_API_TOKEN" > .dev.vars.production
npm run deploy -- --secrets-file .dev.vars.production

The custom domain is the Worker origin, so Cloudflare manages its DNS record and certificate. The Worker serves no workers.dev endpoint and disables preview URLs.

6

Verify Access and inventory

Open the configured hostname in a normal browser. Access should authenticate first, then Fleet should report a read-only session and begin loading the account. Test an unauthenticated private window as well: the Worker itself must reject a request that arrives without a valid Access assertion.

7

Opt into reviewed writes

After reviewing the account boundary, Access policy, proxy allowlist, and read-only inventory, regenerate the same ignored file with --write and deploy again.

cloudflare-fleet hosted configure \
  --account-id "$CLOUDFLARE_ACCOUNT_ID" \
  --database-id "$CLOUDFLARE_FLEET_D1_DATABASE_ID" \
  --hostname fleet.example.com \
  --access-aud "$CLOUDFLARE_ACCESS_AUD" \
  --access-team-domain "$CLOUDFLARE_ACCESS_TEAM_DOMAIN" \
  --write

npm run deploy

Operator policy exceptions

Fleet ships with no policy exceptions. If one zone intentionally uses an exact Email DNS record that differs from the derived fleet baseline, copy fleet-policy.example.json to the per-user Fleet configuration directory and edit the relevant fields. Local launches load it directly; cloudflare-fleet hosted configure validates and embeds the same document into the ignored Wrangler variables.

umask 077
fleet_config_dir="${XDG_CONFIG_HOME:-$HOME/.config}/cloudflare-fleet"
mkdir -p "$fleet_config_dir"
cp fleet-policy.example.json "$fleet_config_dir/fleet-policy.json"
cloudflare-fleet hosted configure ...

An Email DNS exception does not hide the matrix difference. It removes only the exact allowed variant from actionable policy drift.

Import existing local intent, activity, and Worker records

When moving an established local fleet to hosted mode, apply all repository migrations first and import the ignored account-scoped state file once. Worker schedule intent and incident history are included when present; legacy state documents receive an empty Worker record document.

cloudflare-fleet hosted import-state

The importer reads the D1 identifier from the ignored Wrangler configuration and refuses to replace populated hosted state. For populated stores, use the reviewed, history-preserving reconciliation workflow below instead of a force import.

Use one shared control plane from every device

Set CLOUDFLARE_FLEET_URL to the protected HTTPS origin and CLOUDFLARE_FLEET_ACCOUNT_ID to its expected account in each CLI or MCP process. D1 becomes authoritative for intent, activity, and Worker records; Cloudflare remains authoritative for live configuration, and the deployed Worker variables supply operator policy exceptions. The local state file is not a synchronized replica.

Load a dedicated Access service token through CLOUDFLARE_FLEET_ACCESS_CLIENT_ID and CLOUDFLARE_FLEET_ACCESS_CLIENT_SECRET. Add an application-specific Service Auth policy containing only that token, preserving the human login and MFA policies. Alternatively, provide an unexpired application JWT through CLOUDFLARE_FLEET_ACCESS_TOKEN. Do not combine credential methods. Follow Cloudflare's service-token instructions; keep values in a private secret manager and process environment, never arguments, URLs, or shared configuration.

Remote clients do not need or forward the Cloudflare account API token. The stdio MCP process connects through the same bounded hosted command API as the CLI; it does not expose a remote HTTP MCP endpoint. A configured hosted URL has no silent local fallback, and local file flags are rejected. cloudflare-fleet dashboard opens that URL; deployment policy controls writes.

export CLOUDFLARE_FLEET_URL="https://fleet.example.com"
export CLOUDFLARE_FLEET_ACCOUNT_ID="your-account-id"
cloudflare-fleet config show
cloudflare-fleet doctor --live
cloudflare-fleet mcp

Before cutover, stop writers and back up both stores. Apply all repository D1 migrations before deploying matching Worker and client versions. 0004_shared_control_state.sql adds account-scoped state archives, and the Worker diagnostics migration supplies the shared lease. The live doctor checks authenticated protocol, account binding, and required storage tables.

umask 077
CLOUDFLARE_FLEET_BACKEND=local cloudflare-fleet state export > local-backup.json
cloudflare-fleet state export > hosted-backup.json
jq '{state: ., intentSource: "incoming"}' local-backup.json > reconciliation.json
cloudflare-fleet state plan --input reconciliation.json --format json
cloudflare-fleet state apply --input reconciliation.json --expect-plan REVIEWED_DIGEST

Review the complete plan and choose incoming or hosted intent explicitly. Reconciliation preserves distinct activity and incident histories and rejects conflicting identities or pending operations. It rechecks revisions under exclusion, archives the prior state, atomically saves the merge, and verifies persistence. Inputs are bounded to 2 MiB and each apply to 500 additional activities. state export --archive-id ID reads a recovery copy; plan that copy as incoming to restore intent without deleting newer history. MCP provides get_fleet_state, plan_state_reconciliation, and apply_state_reconciliation with signed interactive approval for apply.

After cutover, keep standalone mode for deliberate offline inspection or recovery only. Do not alternate production writes between unsynchronized local and hosted stores. Revoke a lost device's Access token and issue a replacement limited to this application; a lost device does not require distributing the account API token.

Recover Worker diagnostics and schedule management

Run npm run db:migrate:remote before deploying a version that uses Worker diagnostics. 0002_worker_diagnostics.sql adds account-scoped intent and incident documents plus the Worker execution lease. Local state needs no manual migration: the optional workers section is created when intent or evidence is saved. Preserve it with the operation activity section in private backups.

Hosted browser, CLI, and MCP operations share an account-scoped write lease. An interrupted operation can leave pending activity, which blocks writes even after lease expiration. Stop old clients and independently inspect affected live resources, then use cloudflare-fleet recovery plan and recovery apply, or MCP plan_activity_recovery and apply_activity_recovery. Input requires activityId, an investigation reason, and stoppedClientsAndInspectedResources: true; apply requires the exact reviewed digest. Recovery retains the original plans as a failed execution with an explicitly unknown outcome, zero confirmed completions, and no automatic inverse. It does not retry, reverse, or verify Cloudflare writes. A verified inverse requires unchanged post-write schedules and deployment, not merely an available lease.

Online schedule edits do not change the owning Wrangler configuration. Record the configuration owner and reviewed reconciliation step in schedule intent, deliberately make that companion edit in its owning project, and review it again for rollback. Omitted Cron configuration preserves deployed schedules, while an explicit empty array removes them; Cloudflare documents both behavior and the propagation delay in Cron Triggers.

Use the dashboard's Workers panel, cloudflare-fleet worker --help, or the CLI and MCP workflow to inspect, review, apply, verify, and recover the same bounded operation. No recovery step implicitly redeploys code or changes routes, bindings, credentials, or databases.

Keep the local interfaces

Standalone local mode remains available, but it is a separate authority, not a replica of hosted D1. Select it explicitly when a hosted URL is configured. On macOS, provide the account token and identifier in the shell and launch the ordinary browser workflow. It shares the same UI, policy, intent schema, write planner, activity model, and verification code.

export CLOUDFLARE_FLEET_BACKEND=local
export CLOUDFLARE_API_TOKEN="your-account-token"
export CLOUDFLARE_ACCOUNT_ID="your-account-id"
cloudflare-fleet dashboard

Use cloudflare-fleet dashboard --write for the full local workflow. State defaults to $XDG_STATE_HOME/cloudflare-fleet/state.json, falling back to ~/.local/state/cloudflare-fleet/state.json; policy uses the corresponding per-user configuration directory. Select another profile with --state-file or --policy-file. The checkout-local ./launch.sh wrapper accepts the same dashboard options.

The local fleet CLI and stdio MCP server inherit the same credentials and use the same durable state profile:

cloudflare-fleet alignment list --format json
cloudflare-fleet mcp

An MCP client should use cloudflare-fleet as its command and ["mcp"] as its arguments. Keep the token in the inherited process environment, not a tracked or shared client configuration. The server opens no listener and exposes only named diagnostic, audit, intent, alignment, bounded change, activity, and guarded undo tools. The MCP setup guide includes copyable Codex and Claude Code configuration.

Keep the repository safe to publish

Operator state, deployment configuration, live screenshots, and browser traces stay outside version control. Validate the public source tree before proposing a change.

npm run check:publication

The publication check rejects private operator filenames, machine-local paths, unexpected symbolic links, malformed screenshots, and broken documentation links.
